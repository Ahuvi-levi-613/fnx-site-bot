# בוט לאתר הפניקס (fnx-site-bot)

בוט שיחה בעברית שעונה על שאלות **רק** מתוך האתר הציבורי של הפניקס (fnx.co.il), וכל תשובה מצרפת קישור לעמוד המקור.
כשהמידע לא מופיע באתר, הבוט אומר זאת במפורש ומציג את דרכי הקשר מעמוד "צור קשר".

פרויקט לאתגר הפניקס בהאקתון "קוד פתוח 2026". ערב הגמר: 28.10.2026. האפיון המלא נמצא במסמך האפיון של הפרויקט.

## היקף הגרסה הראשונה

ביטוח רכב, ביטוח דירה, ביטוח נסיעות לחו"ל ושירות לקוחות, מתוך עמודי אינטרנט בלבד. קבצי PDF יתווספו בשדרוג עתידי.

## ארכיטקטורה

```
איסוף:   fnx.co.il ─► מיפוי (robots + sitemap, סינון לפי תחום) ─► Firecrawl / גיבוי ישיר ─► ניקוי ─► חיתוך ─► data/chunks.jsonl
אינדקס:  chunks ─► Voyage AI embeddings (גיבוי ל-Gemini Embedding 2, שהמכסה החינמית שלו קטנה מדי) ─► Chroma מקומי (data/chroma)
מענה:    שאלה ─► אחזור היברידי (סמנטי + מילות מפתח) ─► Cohere Rerank ─► Gemini Flash (גיבוי: Groq, OpenRouter) ─► FastAPI ─► דף צ'אט מימין לשמאל
```

כלל הברזל: אין מקור, אין תשובה.

## סטטוס

| יום | מה | מצב |
| --- | --- | --- |
| 1 | הקמה, סריקת התחומים, ניקוי, חיתוך, אינדקס ב-Chroma | ✅ קוד מוכן, ממתין להרצה על האתר |
| 2 | שכבת התשובה: אחזור היברידי, דירוג מחדש, פרומפט מחייב, בדיקת מקור, מעבר לגיבוי | ⏳ |

| 4 | 30 שאלות בדיקה + 5 שיחות המשך, שיפורים והגשה | ⏳ |

## יום 1: איסוף ואינדקס

```bash
python scripts/hebrew_check.py     # בדיקה שמודל ההטמעה מבין עברית (דורש GEMINI_API_KEY)
python scripts/crawl.py map        # מיפוי: כמה עמודים נמצאו בכל תחום
python scripts/crawl.py fetch      # סריקה מנומסת (ממשיכה מאיפה שעצרה; מטמון ב-data/raw/)
python scripts/crawl.py process    # ניקוי וחיתוך -> data/chunks.jsonl, סיכום ב-data/stats.json
python scripts/build_index.py      # הטמעות ובניית האינדקס ב-data/chroma

# בדיקה מהירה של האינדקס:
python scripts/build_index.py --query "איך מגישים תביעה על נזקי מים?"
```

### איך נקבע מה נכנס

לכל תחום ב-[`config/crawl.json`](config/crawl.json) יש:
- `url_keywords`: מילים בכתובת העמוד (למשל car, travel). לפיהן נבחרים עמודים במיפוי ונעקבים קישורים בסריקה.
- `text_keywords`: מילים בכותרות העמוד (למשל "ביטוח דירה"). לעמוד שהכתובת שלו לא אומרת כלום, התחום נקבע לפי הכותרות.

`map` מראה כמה עמודים נמצאו בכל תחום, ומה נשאר בחוץ לפי חלקי האתר. אם תחום יוצא 0, מוסיפים לו מילת כתובת מתוך הרשימה שבחוץ ומריצים שוב.
אם כתובות האתר לא כוללות מילים מזהות בכלל, אפשר להריץ `fetch --any-area`: כל קישור באתר ייסרק (עד `CRAWL_MAX_PAGES`), ו-`process` ישאיר רק עמודים מהתחומים.

### מה יוצא

כל שורה ב-`data/chunks.jsonl` היא קטע אחד:

```json
{"id": "…", "url": "https://www.fnx.co.il/…", "page_title": "…", "heading_path": ["ביטוח דירה", "נזקי מים"],
 "text": "…", "chunk_index": 0, "crawled_at": "2026-10-21T08:00:00+00:00", "area": "apartment"}
```

- החיתוך הוא לפי כותרות העמוד, כך שכל קטע יודע לאיזה סעיף הוא שייך. תשובה קצרה בשאלות נפוצות מצורפת לקטע הבא יחד עם השאלה שלה.
- שורות שחוזרות ברוב העמודים (תפריטים, כותרת תחתונה, באנרים) מוסרות אוטומטית.
- ב-Chroma כל קטע נשמר עם הכתובת, הכותרת, התחום ותאריך האיסוף, כדי שכל תשובה תוכל לצטט מקור.
- ההטמעות נשמרות במטמון (`data/embeddings_cache.jsonl`), כך שבנייה חוזרת לא מבזבזת מכסה על קטעים שלא השתנו.

## יום 2: שאלה ותשובה בטרמינל

```bash
python scripts/ask.py "איך מגישים תביעה על נזקי מים?"
python scripts/ask.py "..." --area apartment    # מגביל לתחום: car, apartment, travel, service
```

מריץ אחזור היברידי + Cohere Rerank + LLM (Gemini, גיבוי Groq ואז OpenRouter), ומדפיס תשובה עם קישורי מקור.
אם המידע לא נמצא באתר, מוצגת הודעה מפורשת עם קישור לעמוד "צור קשר".

## יום 3: הרצת שרת הצ'אט

```bash
python scripts/serve.py
```

ואז פותחים בדפדפן: **http://localhost:8000**

זה דף בדיקה זמני בלבד (בלי העיצוב הסופי) — מטרתו לוודא שהשרת, זיכרון השיחה וכרטיסי המקור עובדים.
נקודת הקצה: `POST /api/chat` עם `{"question": "...", "history": [{"question": "...", "answer": "..."}], "area": "..."}`,
מחזירה `{"answer": "...", "sources": [{"url": "...", "page_title": "..."}], "grounded": true/false}`.

## סיכום להגשה

**איך נאסף התוכן:** סריקה מנומסת של fnx.co.il (robots + sitemap, עיכוב בין בקשות), מצומצמת מראש
לארבעה תחומים (רכב, דירה, נסיעות לחו"ל, שירות לקוחות) לפי מילות מפתח בכתובת ובכותרות
([`config/crawl.json`](config/crawl.json)). התוכן נוקה (הסרת תפריטים/כותרות תחתונות חוזרות) וחולק
לקטעים לפי כותרות העמוד, כך שכל קטע יודע לאיזה סעיף הוא שייך. תוצאה: 434 עמודים, 6,243 קטעים.
קבצי PDF לא נסרקים בגרסה הזו (שדרוג עתידי).

**איך נבחר הקטע לתשובה:** אחזור היברידי — חיפוש סמנטי (הטמעות Voyage AI + דמיון קוסינוס ב-Chroma)
וחיפוש מילות מפתח (כולל הסרת אותיות שימוש בעברית: ב/ה/ו/ל/מ/ש/כ) במקביל, ממוזגים לרשימת מועמדים
אחת. Cohere Rerank מדרג אותם לפי רלוונטיות אמיתית לשאלה (ולהקשר השיחה בשאלות המשך) ובוחר את
5 הקטעים הכי טובים. ה-LLM מקבל רק אותם, וחייב לצטט כתובת URL אמיתית מתוכם. אם הוא לא מצטט, או
אומר בעצמו שאין מידע, המערכת מחליפה את התשובה בהודעה מפורשת "לא נמצא באתר" + קישור לעמוד
יצירת קשר - אף פעם לא מנחשת בשקט.

**מגבלות:** עמודי אינטרנט בלבד (לא PDF/טפסים); ארבעת התחומים בלבד; אין גישה לנתוני לקוחות או
לפוליסה אישית - שאלות כאלה מקבלות הסבר כללי מהאתר והפניה לשירות הלקוחות, לא תשובה מומצאת.
ספקי ה-LLM החינמיים יש להם מגבלות תפעוליות אמיתיות שגילינו תוך כדי עבודה (Gemini לפעמים עמוס;
Groq חסום ע"י NetFree על מחשב הפיתוח; המודלים החינמיים ב-OpenRouter משתנים עם הזמן) - ראו
[`docs/SPEC.md`](docs/SPEC.md#deviations-from-this-spec-log) לפירוט.

**איך מרעננים תוכן:** מריצים מחדש את הסריקה (`python scripts/crawl.py all`) - כל קטע נשמר עם
תאריך האיסוף שלו - ואז בונים מחדש את האינדקס (`python scripts/build_index.py`). ההטמעות נשמרות
במטמון מקומי, כך שריענון לא משלם שוב על קטעים שלא השתנו מאז הסריקה הקודמת.
